# LINE 拍照開發票 — 自動化流程總說明

> 建立:民國 115 年 8 月 30 日
> 目的:在 LINE 發票收件器拍照傳入「開票需求」(客人統編、金額、品名),由每小時排程自動辨識,寄確認信給本人,本人回「OK」後自動透過綠界 API 開立電子發票;金鑰未到位前退化為「整理好資料+提醒手動開」模式。

## 一、整體流程

```
LINE 拍照 → 收件器轉寄 Gmail(主旨「LINE發票 - 上傳者」,照片在附件)
  → 排程(Claude Routine,每日 1 次:台灣時間每晚約 21 時)讀信、解照片、分類:
     ├─ 進項發票/收據(廠商開給我們的)→ 貼標籤「開票/非開票需求」,交給 invoice-pipeline 入帳,不再處理
     ├─ 看不出內容(如聊天截圖、計算機畫面)→ 貼「開票/非開票需求」,提醒信中註明請人工確認
     └─ 開票需求 → 擷取欄位 → 寄【開票確認】信給本人 → 貼「開票/待確認」
  → 本人回信「OK」→ 下一輪排程呼叫綠界 API 開立(急件:直接在 Claude 對話說「開票」立即處理,不必等排程)
  → 成功:寄【已開立】通知(發票號碼/隨機碼)→ 改貼「開票/已開立」
  → 超過 20 小時未回覆 → 再提醒一次
```

## 二、狀態管理(Gmail 標籤)

| 標籤 | labelId | 意義 |
|---|---|---|
| 開票/待確認 | `Label_4` | 已辨識、已寄確認信,等本人回 OK(或手動開立後回「已開」) |
| 開票/已開立 | `Label_5` | 發票已開立(API 或手動),流程結束 |
| 開票/非開票需求 | `Label_6` | 進項發票或無法辨識,不走開票流程 |

無任何「開票/」標籤的「LINE發票 - 」信 = 未處理。排程只掃 `subject:"LINE發票" newer_than:2d`。

## 三、進件方式(給本人與員工)

**拍照**(走 LINE 發票收件器),拍下列任一種:
1. **手寫單**:客人統編(8 碼)、抬頭、品名、含稅金額,一張紙寫清楚最保險
2. 客人傳來的統編抬頭截圖 + 金額訊息(注意截圖要包含金額,截半張會被退回補件)
3. 綠界「收款成功通知」畫面截圖(會自動帶訂單編號與金額)

**用寫的**(不用照片):
1. 直接寄信給自己(onlycoffee99@gmail.com),**主旨含「開票」**,內文寫統編/抬頭/品名/含稅金額
2. 在任何【開票確認】討論串裡直接回信補資料,系統會一併採計

沒寫統編 = 視為個人戶(B2C);金額看不清楚一律不會自動開,會退回確認信。

## 四、綠界 API 金鑰(全自動的前提)

- 取得:綠界廠商後台 → 系統開發管理 → 系統介接設定,抄下 **MerchantID、HashKey、HashIV**(電子發票介接專用那組)
- 存放:Google 雲端硬碟根目錄,檔名 **`綠界API金鑰.json`**,內容:
  ```json
  {"MerchantID":"3099012","HashKey":"...","HashIV":"..."}
  ```
- **禁止**把金鑰 commit 進本 repo 或寫進任何會推上 GitHub 的檔案。
- 兩家商店(鑫和洋行 3099012/公園一館 3451196)金鑰不同;預設用檔案內那組,如需分店開立,檔案改為陣列並以 `store` 欄位標記。

## 五、網路白名單(全自動的前提之二)

本雲端環境對外連線走白名單,綠界 API 預設被擋(403 "Host not in allowlist")。
需在 claude.ai/code 的環境設定(Environment → Network egress)加入:

- `einvoice.ecpay.com.tw`(正式)
- `einvoice-stage.ecpay.com.tw`(測試,建議一併加,首次串接先打測試環境)

## 六、開立工具

`tools/einvoice/issue.js`(Node,無相依套件):

```bash
node tools/einvoice/issue.js --config 金鑰.json --data 發票資料.json [--stage]
```

發票資料格式見該檔案開頭註解。重點檢核:品項含稅金額加總必須等於 SalesAmount;有統編不可帶載具;統編必為 8 碼數字。成功輸出 `{ok:true, InvoiceNo, InvoiceDate, RandomNumber, RelateNumber}`。

✅ 已於 115/8/30 實測通過:測試環境成功開立測試發票(LA25031805);正式環境以金鑰做唯讀字軌查詢成功(查得 115 年 9-10 月 FW 字軌已設定)。發送一律走 curl(環境須經代理,Node https 不會自動走代理)。

## 七、從 Gmail 信件解出照片(排程用)

Gmail MCP 沒有附件下載工具,用 `get_message` 的 **RAW** 格式(結果超長時會自動存檔到 tool-results 目錄),再解 MIME:

```bash
node -e '
const fs=require("fs");
const j=JSON.parse(fs.readFileSync(process.argv[1],"utf8"));   // RAW 結果檔路徑
const mime=Buffer.from(j.raw.replace(/-/g,"+").replace(/_/g,"/"),"base64").toString("binary");
for(const p of mime.split(/--[0-9a-zA-Z=_.()+-]+\r?\n/)){
  if(/image\/jpeg/i.test(p)){
    const b64=p.split(/\r?\n\r?\n/)[1];
    if(b64) fs.writeFileSync(process.argv[2],Buffer.from(b64.replace(/\s/g,""),"base64"));
  }
}' <RAW結果檔> <輸出.jpg>
```

解出後用 Read 工具檢視照片內容進行分類與欄位擷取。

## 八、安全鐵律(排程必守)

1. **未收到本人明確「OK」回覆前,絕不呼叫開立 API**。確認信寄出 ≠ 授權。
2. 金額、統編任一項辨識不確定 → 只寄確認信,不開立;確認信中標明不確定處。
3. 發票開立不可逆(作廢需折讓程序),寧可多一輪確認,不可搶快。
4. 開立成功必寄通知信留底(發票號碼、隨機碼、金額、RelateNumber),並回填標籤。
5. 排程如遇 API 403(白名單)或金鑰缺失,自動退化為「提醒手動開」模式,不得報錯了事。
6. **成本鐵律(115/9/2 訂)**:開立 API 若再被權限系統擋下,不重試、不排錯、不開子對話測試——自動開立就地**永久降級**為「整理欄位+提醒手動開」。手動在綠界後台開一張約 3 分鐘,任何排錯都比它貴。
