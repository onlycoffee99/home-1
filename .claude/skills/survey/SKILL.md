# 舞荳問卷設計 工作模式

「舞荳問卷設計 ・ 0975-328-779」是老闆(Eileen)的問卷服務品牌。產品=**客人掃 QR → 抽籤式隨機答題(像遊戲)→ 抽籤詩+券號 → 櫃台換贈品券**,資料自動進 Google 試算表,每月出統計報告。第一個作品是森林風呂御神籤(115/9/27 上線)。

## 開工必讀
1. `行銷/森林風呂御神籤/部署說明.md`(網址、題目結構、櫃台發券、統計口徑)
2. 要改程式時讀 `Index.html`(題庫在 `<script>` 開頭)與 `Code.gs`(`COLUMNS` 欄位表)
3. `tools/README.md` 的 survey_report.py、make_qr.py、html2pdf.js 段落

## 系統架構(兩個檔 + 一份試算表)
- `Index.html`:前端,題庫 = `OVERALL`(第 1 題)+`CORE`(固定)+ 各 `POOL_*`(隨機抽)+ 基本資料卡;`buildSet()` 決定每人抽幾題。直接用瀏覽器開=預覽模式(券號 DEMO,不存資料)。
- `Code.gs`:Google Apps Script 後端。`submit()` 寫一列、券號=列數流水號、台灣時間、防公式注入;`doGet(?export=<金鑰>)` 回傳全部資料 JSON。
- 試算表:「回覆」工作表,一列一人,沒抽到的題留空,`asked` 欄記本次抽到的題 id。
- 金鑰:Apps Script「專案設定 → 指令碼屬性」`EXPORT_KEY`;另存一份在客戶雲端硬碟資料夾的「匯出金鑰(勿外流)」文件。**金鑰不得寫進 repo。**

- `Code.gs` 的 `DAILY_LIMIT` 控制每日發券上限;改數量要請老闆改這一行後發布新版本。額滿的填答仍計入統計(券號欄「今日額滿」)。

### 做報告(老闆說「做問卷報告 X 月」「做 X~Y 月報告」)
1. 金鑰:Drive `read_file_content` 讀「御神籤_匯出金鑰(勿外流)」(ID `1dhya2r9p-0-HSzNqP-j1zm882m6t0P-5NL7xpd-N5m8`)。
2. `python3 tools/survey_report.py --url <網址> --key <金鑰> --month 2026-10 --out 行銷/森林風呂御神籤/報告/115年10月.md --save-json <scratchpad>/raw.json`

   - 留言含「Claude 測試」的列自動排除。
3. 在「重點摘要」後補 3~5 行觀察:**只寫數據看得到的事實**,不推論原因、不評價人員(CLAUDE.md 鐵律 2)。

### 改題目 / 改文字
1. 改 repo 內 `Index.html`(與 `Code.gs`)→ 本機 Playwright 跑一遍(見下方「驗證」)。
2. **題目 id 不得改動或重用**(報告靠 id 對欄位)。新題給新 id,並在 `Code.gs` 的 `COLUMNS` **最後面**加欄位(舊資料欄位不動,程式會自動補標題列);`tools/survey_report.py` 的 `SECTIONS`/`TRAVEL`/`FUN` 同步加。
3. 交給老闆貼上:**完整程式碼放在對話的 code block**(HTML 檔傳檔案卡會被預覽成網頁,無法複製原始碼)。只改一兩行時,告訴她用 Ctrl+F 找哪一行改成什麼。
4. 重新部署步驟(每次都要講清楚):部署 → **管理部署作業** → 左邊先點「使用中」那筆 → 鉛筆 ✏️ → 版本選「**新版本**」→ 部署。**絕不可用「新增部署作業」**(會換網址,QR 立牌作廢)。
5. 改完用 curl 確認線上已更新(例:`curl -sSL <網址> | grep -o 關鍵字`)。

## B. 新客戶案(接案流程)

1. **需求訪談**(一次問完):店名/場域、想知道什麼(3~5 個重點)、贈品是什麼(金額、使用店家、期限)、資料要給誰看(自用/送公部門)、每月大約幾位客人、對方有沒有 Google 帳號。
2. **題目設計**:總題數 8~10;每人必答 = 整體滿意 + 2~3 題核心 + 基本資料;其餘分類抽(每類至少抽 1,報告才有各類數據);滿意度一律五級文字+表情(非常滿意~非常不滿意),答不出來的題加「不清楚」類選項;趣味題 1 題;不蒐集個資。先出題目清單給老闆確認再寫程式。
3. **建檔**:複製 `行銷/森林風呂御神籤/` 到 `問卷案/<客戶名>/`,改題庫、主題名稱與配色、贈品文字、署名;`Code.gs` 改 `COLUMNS` 與 `SPREADSHEET_ID`。
4. **部署在客戶自己的 Google 帳號**(資料歸客戶):我們用 Drive 可建的只有自己帳號的試算表,所以通常由客戶(或老闆在現場用客戶帳號)照 `部署說明.md` 做:建試算表 → script.google.com 新專案 → 貼兩個檔 → 設 `EXPORT_KEY` → 部署(執行身分「我」、存取「所有人」)→ 授權(「進階 → 前往(不安全)→ 允許」是正常的)。
5. **印刷品**:`python3 tools/make_qr.py <網址> qr.svg` → 嵌進立牌 HTML(參考 `立牌_A5.html`)→ `node tools/html2pdf.js 立牌.html 立牌.pdf 預覽.png`;贈品券參考 `咖啡券_A4十張.html`(A4 裁 10 張名片)。QR 印出前用 OpenCV 解碼預覽圖確認網址。
6. **報告**:`survey_report.py` 目前的 `SECTIONS/TRAVEL/FUN` 與標題是森林風呂專用;新客戶複製成 `問卷案/<客戶名>/report.py` 或把常數改成讀設定檔,不要改壞森林風呂版。
7. **交付**:上線網址、立牌 PDF、券 PDF、櫃台發券說明、第一份報告範例。

### 接案鐵律
- 每個客戶的資料只屬於該客戶;**作品展示、提案、範例一律用假資料**,不得拿森林風呂或其他客戶的真實數字。
- 網頁頁尾小字署名「舞荳問卷設計 ・ 0975-328-779」(署名前確認客戶同意);**要送公部門的報告不署名**。
- 贈品券條款必寫:限用店家、每次限 1 張、有效期限、不兌現不找零;免費贈送券不是預收款禮券,但券面仍寫清楚「贈品」。
- 要收 email/電話:一律**選填+勾選同意+個資說明**(蒐集者=客戶公司名、目的、類別、期間地區對象方式、當事人權利與聯絡方式、不提供不影響贈品),照森林風呂版的寫法;個資欄放進 `PRIVATE_COLUMNS`,不進匯出與報告。
- 報價參考(老闆自訂,非市場調查):建置 NT$8,000~15,000、月報告 NT$1,500~3,000/月;收費要開發票,用哪個統編開先請記帳士確認營業項目。
