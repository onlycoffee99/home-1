# 兩家商號會計工作模式

## 開工順序
1. 讀 `記帳/會計制度說明.md`(制度全文:組織型態稅制、科目表、稅務時程、薪資流程)。
2. 開票相關再讀 `記帳/開票自動化_總說明.md`(金鑰位置、RAW解碼指令、安全鐵律)。
3. 盤點 Gmail 標籤:`開票/待確認`(Label_4)、`開票/已開立`(Label_5)、`開票/非開票需求`(Label_6)。

## 分類與入帳鐵則(不得用直覺)
1. **以買方統編分流**:72941298→鑫和;92629289→公園一館;兩者皆非→待核清單;賣方=任一家→該公司收入(綠界/iCHEF已有紀錄,不重複入帳)。
2. **發票號碼=唯一鍵,自動去重**:登帳前先查兩份總帳,號碼已存在→不重登,只在既有列備註補來源(如「照片與郵件重複」);金額不一致→以票面為準更正並備註。
3. **每張照片/郵件發票都要落帳**;註明「個人」→個人費用;無法判定→公司帳科目「待歸類」;手寫收據判讀不全→待核清單。
4. 金額欄缺漏(附件PDF未解)→先登帳留空+備註待補,申報前解附件補齊。
5. 薪資:主旨含「薪資」的信,一律登鑫和(老闆指示統一由鑫和申報),科目「薪資」;公司負擔勞健保/勞退另列「勞健保」;員工身分證等個資存 Google Drive「員工基本資料」,不進 repo。
6. 總帳/待核清單有異動即 commit+push(commit 訊息簡述筆數金額)。

## 開票流程(銷項)
1. 欄位:買受人統編(8碼,個人戶留空)、抬頭、品名、含稅金額、Email(選填)。缺→確認信標明缺什麼。
2. 寄【開票確認】到 onlycoffee99@gmail.com,貼 Label_4;本人回「OK」且欄位齊→從 Drive 讀 `綠界API金鑰.json` 存 scratchpad,跑 `node tools/einvoice/issue.js --config <金鑰> --data <資料>`;成功→回信【已開立】,改 Label_5 移除 Label_4,登該公司收入。
3. 本人回「已開」→直接 Label_5+登收入。Label_4 超過 20 小時→原串提醒一次(僅一次)。

## 排程(成本設計,勿擅自加頻)
- 【開票排程-每日1次】每晚台灣 21 時:合併搜尋 `{subject:"LINE發票" subject:開票} newer_than:2d`,處理照片/文字件、Label_4 追蹤;急件由使用者說「開票」即時處理。
- 【記帳-每月報表】每月 1 日 21 時:收薪資信→掃上月廠商發票信(去重)→兩家損益表 Excel SendUserFile 給老闆。
- 大批照片(>10 張)→開 general-purpose 子代理批次處理,主對話只收彙總。

## 口令對照
「開票」=立即檢查處理|「月報」=補跑上月報表|「申報」=該期兩家 401 整理包(先解待核附件)|「綜所稅」=全年兩家損益彙整|「扣繳」=全年給付清單

## 安全與成本鐵律(違反=停手)
- 未收到本人「OK」絕不呼叫開立 API;金額/統編不確定只寄確認信;測試需求(統編12345675或註明測試)不真開。
- 開立 API 再被權限系統擋下→不重試不排錯,**永久降級**為提醒手動開。
- 金鑰(HashKey/HashIV)與員工個資絕不 commit 進 repo。
- 開錯家=作廢重開:開立前確認歸屬哪家。
- 法規以申報當年度國稅局公告為準;正式申報前建議記帳士複核。
