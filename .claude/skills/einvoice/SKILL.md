# 開票自動化工作模式

## 開工順序

1. 讀 `記帳/開票自動化_總說明.md`(完整流程、金鑰位置、解碼指令、安全鐵律)。
2. 用 Gmail 標籤盤點現況:`開票/待確認`(Label_4)=等本人回覆;`開票/已開立`(Label_5)=結案;`開票/非開票需求`(Label_6)=已濾除。

## 兩個進件管道

- **照片**:Gmail 搜 `subject:"LINE發票" newer_than:2d`,get_message RAW 解出 jpg(解碼指令見總說明第七節),Read 檢視分類。進項發票/無法辨識→Label_6;開票需求→擷取欄位。
- **文字**:Gmail 搜 `subject:開票 newer_than:2d`(本人自寄、排除系統寄的【開票確認】【已開立】【待開發票】),直接從信文擷取欄位。討論串裡本人用文字補充的資料一併採計。

## 開立流程

1. 欄位:買受人統編(8碼,個人戶留空)、抬頭、品名、含稅金額、Email(選填)。缺任一項→確認信標明缺什麼。
2. 寄【開票確認】信到 onlycoffee99@gmail.com 列出全部欄位,貼 Label_4。
3. 本人回「OK」且欄位齊全→從 Google Drive 讀 `綠界API金鑰.json` 存到 scratchpad(勿放 repo),執行:

```bash
node tools/einvoice/issue.js --config <金鑰.json> --data <發票資料.json>
```

發票資料格式見 `tools/einvoice/issue.js` 開頭註解。成功→回信【已開立】附發票號碼/隨機碼/金額,改貼 Label_5、移除 Label_4。
4. 本人回「已開」(手動開了)→直接改貼 Label_5。
5. Label_4 超過 20 小時無回覆→原討論串再提醒一次。

## 安全鐵律(違反=停手)

- 未收到本人明確「OK」回覆,絕不呼叫開立 API;確認信寄出≠授權。
- 金額或統編任一辨識不確定→只寄確認信,標明不確定處。
- 測試性質需求(統編 12345675、註明「測試」)一律不真開;要驗證程式用 `--stage` 打測試環境。
- 發票開立不可逆(作廢需折讓),寧可多問不可搶快;開立成功必寄通知留底。
- 金鑰(HashKey/HashIV)絕不 commit 進 repo、絕不寫進會推上 GitHub 的檔案。
